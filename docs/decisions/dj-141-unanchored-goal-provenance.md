## DJ-141: Goal-Layer Provenance — `anchored` / `unanchored` Split Gates Non-Destructive Re-Sync; Honest Bootstrap Tagging Replaces Fabricated `source_clause`; Matcher Gains `promoted` + `contradicted` Moves; `synced_at` Server-Stamped — Follow-Up to DJ-139

**Status:** settled (designed 2026-05-27; no code yet). Follow-up to [DJ-139](dj-139-goal-layer-node-kinds.md), which shipped the goal layer but modelled every goal as verbatim-anchored to `GOALS.md`. This DJ corrects that model after the first real bootstrap (winplan) exposed the gap.

**Context.** DJ-139 persists the LLM's interpretation of `GOALS.md` as `goal-*` / `agoal-*` leaf nodes, and guarantees "diff-and-apply, never wipe-and-regen" id-preservation across `GOALS.md` edits. That guarantee rests on RQ7: `source_clause` is "the verbatim excerpt from `GOALS.md`" and the matcher preserves ids by matching stored `source_clause` against current `GOALS.md`. RQ9 makes the scope-decision bootstrap **one-time** — subsequent syncs read `GOALS.md` as the sole claim source.

The first real bootstrap (winplan, session `20260527`, `refine goals` via `/locutus-refine`) revealed that pairing is contradictory in practice. winplan's `GOALS.md` carries a one-line mission statement and **empty** `## In Scope` / `## Out of Scope` sections. The existing spec graph (decisions, features, strategies) was already built; its axes had been driven by goals the original refine pass *inferred* — partly from explicit scope text, but substantially from **implicit scope in the mission statement itself** ("a web app to help win elections" implies voter targeting, win-number computation, field planning, and a large set of out-of-scope carve-outs) and from deliberation crystallized into decisions like `dec-product-scope-boundary`. Those inferred goals were ephemeral under pre-DJ-139 Locutus and were lost — which is exactly why a later `import` of a dashboard feature collided head-on with a cost decision with no structural landing surface (the trigger for DJ-139 itself).

On bootstrap the matcher correctly recovered the inferred goals from the scope-encoding decision bodies (RQ9's affordance). But DJ-139's `added` schema demands `source_clause` = "verbatim excerpt from current `GOALS.md`," and for an inferred claim there is no such excerpt. The matcher had no legal move and **fabricated** `GOALS.md`-shaped `source_clause` strings (18 of 19 winplan nodes carry clauses that do not appear anywhere in `GOALS.md`; the lone real match is the mission paragraph). This is benign on its own — the nodes' bodies are good — but it primes a destructive failure: on the **next** sync (triggered by any `GOALS.md` edit), the matcher runs in non-bootstrap sole-source mode, finds none of those `source_clause` values in `GOALS.md`, classifies all the inferred goals as `deleted`, and orphans every `.advances` / `.respects` citation just written onto the graph. The goal layer evaporates again on the first edit — reintroducing the unbounded-blast-radius failure mode DJ-139 set out to kill, now hidden behind a layer that *looks* stable until you touch `GOALS.md`.

The root cause is a model error, not a prompt bug: **DJ-139 assumes every goal is verbatim-anchored to `GOALS.md`, but the layer's whole reason to exist is the goals that are not** — the implicit-from-mission and deliberation-inferred ones.

**Decision.** Add a provenance distinction to the goal layer and re-gate the matcher's deletion semantics around it. No new node kinds, no new verbs, no migration.

1. **Two provenance classes: `anchored` / `unanchored`, with `source_clause` presence as the signal.** An **anchored** node has a non-empty `source_clause` (a verbatim `GOALS.md` excerpt, as in DJ-139). An **unanchored** node has an empty/omitted `source_clause` and instead carries a new optional `origin string` — a free-text, non-behavioral note recording where the claim came from (`"mission statement"`, `"dec-product-scope-boundary"`). "Anchored" is *defined as* `source_clause != ""`; there is no redundant boolean or enum (rejected to avoid two sources of truth for one fact, per [[feedback-no-aspirational-fields]]). The provenance class's **only** job is to gate matcher behavior.

2. **`origin` field on `GoalNode` and `AntiGoalNode`.** Optional `string`. The `spec_propose_goal` / `spec_propose_antigoal` tools gain an optional `origin` parameter and make `source_clause` optional, but enforce **exactly one of** `{source_clause, origin}` — never neither — so "unanchored" is always an explicit, intentional state with a recorded reason, not an empty default that masks a forgotten `source_clause`. `ceded_to` / `kept_in` on `AntiGoal` are unchanged.

3. **Delete-by-absence gated to anchored nodes only.** This single gate is the core fix. The matcher's `deleted` category fires only for **anchored** nodes whose `source_clause` no longer appears in `GOALS.md`. An **unanchored** node never claimed a `GOALS.md` clause, so absence-from-`GOALS.md` cannot retire it. Unanchored nodes persist by default and are retired only on a positive signal: a `GOALS.md` edit that promotes (§5) or contradicts (§6) them, or an operator's explicit `spec_delete_goal` / `spec_delete_antigoal`. There is no graph-structural retirement — goals are leaves; the cascade cites *up* to them and nothing below them can retire them.

4. **Matcher receives provenance and walks an extended decision tree.** Each existing node is passed to `spec-goal-diff-matcher` tagged anchored/unanchored. For each incoming `GOALS.md` claim the matcher checks, in order: matches an anchored node's `source_clause` (→ `unchanged` / `modified`) → matches an **unanchored** node's `body` at the same polarity (→ `promoted`, §5) → contradicts any node at opposite polarity (→ `contradicted`, §6) → else `added`. Unanchored nodes with no corresponding incoming claim are invisible to the matcher and fall through to `unchanged` untouched.

5. **New `promoted` move.** A new or newly-explicit `GOALS.md` clause that semantically matches an existing **unanchored** node's `body` (same polarity) is a promotion, not a new node. The orchestrator calls `spec_revise_goal` / `spec_revise_antigoal` to set `source_clause` to the verbatim clause and clear `origin`, **preserving the id**. This is the "add the budget scope to `GOALS.md` and have the inferred goal just bind to it" path — no duplicate node, no orphaned citation. The previously-inferred goal becomes explicit in place.

6. **New `contradicted` move — auto-resolve toward `GOALS.md`.** A new `GOALS.md` clause that asserts the opposite polarity of an existing node (an in-scope assertion against an `agoal-*` that cedes it, or vice versa) is a contradiction. Polarity lives in the node *type* (`goal-` vs `agoal-` prefix), so there is no id-preserving in-place flip. `GOALS.md` is canonical, so the contradicting edit **wins automatically**: the matcher emits `{retire_id, new_node, citing_ids}`; the orchestrator deletes the contradicted node (`spec_delete_antigoal` + `antigoal_deleted` audit event, or the goal variant), mints the new-polarity node, and the citation walk re-anchors `.advances` / `.respects` metadata. Because the citation walk only re-anchors metadata and never rewrites feature *content*, the orchestrator **also surfaces `citing_ids` as at-risk findings** — the scope call is automatic, the downstream content review is flagged, not silently assumed done.

7. **Honest bootstrap tagging.** The one-time bootstrap (RQ9 of DJ-139, otherwise intact) stops inventing `GOALS.md` excerpts. Claims derived from a scope-encoding decision body or the implicit mission are minted **unanchored** — empty `source_clause`, `origin` set to the backing decision id or `"mission statement"`. Only claims with genuine verbatim In/Out-of-Scope text in `GOALS.md` at bootstrap time are minted **anchored**. The matcher's bootstrap `added` entries carry `origin` instead of a back-formed `source_clause`. This is the change that prevents the fabrication at the source.

8. **No migration.** winplan (the only project with a goal layer bootstrapped under DJ-139) will be reset to a clean slate — `GOALS.md`, decisions, features, strategies present; no `goal-*` / `agoal-*` nodes — and re-bootstrapped under DJ-141, which tags provenance correctly from the start. No other project carries a bootstrapped layer. A version-gated migration pre-pass and a standalone `locutus migrate-goals` verb were both considered and dropped as machinery for a problem that won't exist after the reset.

9. **Unanchored scope made visible.** `locutus status --full` splits goal-layer counts into anchored vs unanchored and lists unanchored goals under an informational (not at-risk) heading — *"inferred scope not yet stated in `GOALS.md` — candidates to make explicit."* `locutus explain <goal-id>` shows `origin` for unanchored nodes. This is the operator-facing payoff of the hybrid model: implicit scope you can see and choose to promote into `GOALS.md`, rather than scope buried in decision bodies. Extends existing read surfaces; no new verb.

10. **`synced_at` server-stamped.** Drop `synced_at` from the `spec_update_goals_md_hash` tool input schema and always stamp `time.Now().UTC()` in the handler. The agent has no clock; the sync time is authoritatively the server's. ([tools_spec_write.go](../../internal/mcp/tools_spec_write.go) already has the server-side fallback — this removes the agent's ability to override it, which on the winplan run produced a fabricated `2026-05-27T00:00:00Z` midnight timestamp.)

**Resolved design questions** (chat 2026-05-27):

1. **A goal with no `GOALS.md` sentence is legitimate and persistent — hybrid model.** Goals inferred from the implicit mission or crystallized into decisions are first-class durable nodes, not transient gaps. Rejected: "must anchor to `GOALS.md`" (would force the entire implicit mission scope to be enumerated as prose — high friction and likely incomplete). The user ruled this out explicitly. Also clarified: goals are always leaves whose only conceptual parent is the `GOALS.md` root; there is no child "backing node," so retirement of an unanchored goal is signal-based (§3), not structural.

2. **Two provenance classes, not three.** `anchored` / `unanchored`, because the only behavior the class gates is whether delete-by-absence may fire. A three-way `explicit` / `implicit` / `inferred` split was rejected: it would only earn its keep if implicit (mission-derived) goals were re-derived from the mission line on edits while inferred ones weren't — but re-deriving reintroduces the non-determinism this layer exists to kill, so the distinction is behaviorally inert. Mission-vs-decision origin is preserved as a free-text `origin` note for human readability, driving no logic.

3. **Contradiction auto-resolves toward `GOALS.md`, not surface-only.** A contradicting `GOALS.md` edit wins automatically (delete the conflicting node, mint the new-polarity node) because `GOALS.md` is canonical and edits should flow through the graph — the operator's lever for resolving a scope conflict is editing `GOALS.md`, not manual node surgery. Rejected: surface-only / never-auto-flip (the conservative option; rejected because it leaves the operator doing the manual work the goal layer was meant to absorb — the dashboard-collision pain). The downstream-content-review surfacing (§6) is the guardrail that keeps "automatic" from meaning "silent."

4. **Provenance representation: `source_clause` presence is the signal (+ `origin` note).** One new optional field (`origin`), "anchored" defined as `source_clause != ""`, tools enforce exactly-one-of. Rejected: an explicit `provenance` enum alongside `source_clause` (two sources of truth for one fact; can drift; aspirational shape per [[feedback-no-aspirational-fields]]).

5. **No migration; winplan reset and re-bootstrapped.** Rejected: a manifest `goal_layer_version`–gated reclassification pre-pass and a standalone migration verb (machinery for a one-project, one-time problem the reset eliminates; over-fragmentation per DJ-139 RQ9's reasoning).

**Alternatives considered:**

- **Force the matcher to always produce a verbatim `source_clause` (status quo, treat fabrication as a prompt bug to fix).** Rejected — the fabrication is a symptom of a model error. There genuinely is no `GOALS.md` excerpt for an inferred goal; demanding one either fabricates or fails. The fix is to model the absence honestly, not to prompt harder.

- **Demote-on-absence instead of delete-on-absence for anchored nodes** (an anchored node whose clause vanishes becomes unanchored rather than deleted). Rejected — it conflicts with §3's delete-by-absence rule and with the canonical-`GOALS.md` stance: removing a clause is a deliberate retirement signal, and silently keeping the goal as unanchored would let retired scope linger invisibly. Removal should retire (with downstream surfacing), consistent with the `contradicted` posture.

- **Re-derive implicit (mission-anchored) goals from the mission statement on every sync.** Rejected per RQ2 — re-derivation is non-deterministic and reintroduces the blast-radius problem; persistence-by-default is the whole point.

- **A `goal_layer_version` manifest field + migration pre-pass.** Rejected per RQ5 — no project needs it once winplan is reset.
