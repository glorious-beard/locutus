## DJ-139: Persist the LLM's Interpretation of `GOALS.md` as First-Class `goal-*` and `agoal-*` Graph Nodes with Polarity Encoded in the Node Type; `.advances` / `.respects` as Informational Dotted-Line Citations on Decisions/Features/Strategies/Approaches (Optional, Not Required Invariants); `goals_md_hash` in `.borg/manifest.json` as the Short-Circuit Signal for `refine goals` Sync; Diff-and-Apply Sync Algorithm (Never Wipe-and-Regen) Preserving IDs Across `GOALS.md` Edits via LLM-Judgment Matching Against `source_clause` Anchors; `refine goals` Workflow Reorganized as Sync → Iterate → Cite (Citation Walk Last to Operate Against Final State); One-Time Bootstrap Affordance Treats Existing Scope-Encoding Decisions Like `dec-product-scope-boundary` as Secondary Sources on First Run

**Status:** shipping (designed 2026-05-27; implemented 2026-05-27 across 8 phases in `main`; Phase 9 — this section — docs updated and status flipped). Phase 1 — `spec.Goal` / `spec.AntiGoal` types + `SpecStore` extension with `.borg/spec/goals/` and `.borg/spec/antigoals/` persistence; Phase 2 — optional `Advances` / `Respects` citation fields on Decision / Feature / Strategy / Approach plus matching MCP-tool input fields; Phase 3 — six MCP write tools (`spec_propose_goal`, `spec_revise_goal`, `spec_delete_goal` and the three AntiGoal variants) plus `goal_deleted` / `antigoal_deleted` history events; Phase 4 — `goals_md_hash` + `goals_md_synced_at` fields on `.borg/manifest.json` with `ComputeGoalsMdHash` helper and atomic store-method update path via `spec_update_goals_md_hash`; Phase 5 — `spec-goal-diff-matcher` canonical agent prompt for the goal-layer diff pass; Phase 6 — `refine goals` workflow reorganized as sync → iterate → cite with hash short-circuit, one-time bootstrap affordance for `dec-*-scope-boundary` style projects, and the at-risk surface for features without goal anchors; Phase 7 — `feature_ingestion` playbook reads the goal layer for structural conflict detection and drafts `GOALS.md` diffs for plausibly-extensible carve-outs; Phase 8 — `locutus status --full` surfaces goal-layer counts plus the "Features without goal anchors" at-risk section; Phase 9 (this section) — docs updated, status flipped. Empirical end-to-end validation against the winplan dashboard scenario deferred to the operator's first real `locutus refine goals` invocation from their own environment.

**Context.** Locutus today derives the entire spec graph (decisions, features, strategies, approaches) from `GOALS.md` via a `refine goals` pass. The LLM's interpretation of `GOALS.md` — which atomic claims it extracted, which axes it surfaced, which boundaries it inferred — is **ephemeral**: it lives only in the agent's session log, not in the persisted graph. Two failure modes follow:

1. **Unbounded blast radius on `GOALS.md` edits.** When the user adds a new goal, the next `refine goals` re-derives the whole graph from scratch because there's no record of which goal-claims justified which existing decisions. A small `GOALS.md` edit ripples through dozens of nodes unnecessarily; without the original ephemeral goals explicitly stated, the new ones heavily bias the next refine pass and the graph drifts in ways the operator can't predict.
2. **Implicit conflict surfaces with no landing.** When an operator runs `locutus import <feature>` and the feature conflicts with a scope claim, the agent has nowhere structural to bind the conflict. It re-reads `GOALS.md` prose every time and re-judges "does this feature touch an out-of-scope area?" — non-idempotent and unauditable.

The concrete trigger was the dashboard import attempt on winplan (session `20260527/0310/010000`): `locutus import docs/dashboard.md` surfaced seven distinct scope conflicts against `dec-product-scope-boundary` and stopped because no surface existed for "extend `GOALS.md` by adding a carve-out." The system blocked, but the only path forward — declaring new scope in `GOALS.md` — would itself trigger failure mode (1) above. The user's observation that surfaced DJ-139: the underlying problem is that `dec-product-scope-boundary` is itself a workaround for a missing goal-layer. Scope claims belong at a layer Locutus doesn't have today.

DJ-139 adds **persisted, structured goal/anti-goal nodes** as the LLM's durable interpretation of `GOALS.md`. The interpretation stops being ephemeral; the graph gains a stable scope-layer that import flows can bind to; `GOALS.md` edits become incremental diffs against the persisted layer rather than full re-derivations. Crucially, the goal layer is a **leaf in the graph cascade sense**: `refine goals` writes through to it but downstream nodes never *structurally* depend on it. Citations from decisions/features/strategies/approaches to the goal layer are **informational dotted lines**, not required invariants — under the coding-agent runtime ([DJ-135](dj-135-multi-runtime-pivot.md)), structural over-prescription would be redundant with the agent's reasoning capacity and would risk degeneracy patterns that pre-DJ-135 direct-SDK calls had to defend against but DJ-135-era runtimes don't.

**Decision.** Add two new prefix-discriminated node kinds (`Goal` and `AntiGoal`), six new MCP write tools (propose/revise/delete for each), optional `.advances` / `.respects` citation fields on existing kinds, a `goals_md_hash` field in `.borg/manifest.json`, and a reorganized `refine goals` workflow (sync → iterate → cite, with citation walk last). Existing MCP tools and graph machinery extended rather than replaced.

1. **Two new node kinds with polarity in the type, not a field.** `Goal` carries `goal-` prefix; `AntiGoal` carries `agoal-` prefix. `validSpecID` regex extends to `^(goal|agoal|feat|strat|dec|bug|app)-...`. Decisions/features/strategies/approaches `.advances` Goals and `.respects` AntiGoals. The field name names the relationship; the LLM doesn't read a `kind` enum on every consumption. Polarity confusion (agent citing a `goal-` id in `.respects` or vice versa) is rejected at the propose/revise tool's id-prefix check.

2. **Minimal node shapes.** `Goal` carries `{id, title, body, source_clause, created_at, updated_at}`. `AntiGoal` carries the same plus `ceded_to []string` (named incumbents owning the ceded space) and `kept_in []string` (carve-out clauses that stay in scope despite the exclusion). No `status` field, no `surfaces_axes` field on the node — both were considered and rejected for lacking immediate consumers (per [[feedback-no-aspirational-fields]]).

3. **`.advances` / `.respects` are optional informational links.** Both fields are `[]string` on Decision, Feature, Strategy, and Approach. Empty or absent is the common case. The agent populates them when there's a clear citation worth recording; the graph never enforces non-empty invariants. Consumers (`locutus explain`, `status --full`'s dangling-ref validation, the import playbook's precedent-hint lookup) handle empty/absent gracefully.

4. **`goals_md_hash` in `.borg/manifest.json` as the short-circuit signal.** Single project-level SHA-256 of the `GOALS.md` bytes at the time the goal layer was last synced, plus `goals_md_synced_at` timestamp. On `refine goals` invocation, hash match → skip step 1 entirely. Hash mismatch (or absent on first run) → run the diff-and-apply sync.

5. **Diff-and-apply on `GOALS.md` change, never wipe-and-regen.** Wiping would break every `.advances` / `.respects` citation on every edit. The sync algorithm dispatches a new `spec-goal-diff-matcher` subagent that receives current `GOALS.md` plus the existing `goal-*` / `agoal-*` nodes (id + source_clause + body + ceded_to + kept_in) and returns a structured diff: `Unchanged`, `Modified` (with id preserved), `Deleted` (with reason), `Added` (with proposed slug). The orchestrator applies the diff via `spec_propose_*` / `spec_revise_*` / `spec_delete_*` calls. `source_clause` is the load-bearing anchor — comparing new GOALS.md against stored source clauses gives the matcher textual grounding, not just semantic vibes. Edge cases (claim split, claim merge, significant rephrasing) handled by the matcher: revise the closest-match candidate, add/delete the residue, prefer preserving the more-cited node when collapsing.

6. **Six new MCP write tools** in `internal/mcp/tools_spec_write.go`: `spec_propose_goal {id, title, body, source_clause}`, `spec_revise_goal {id, title, body, source_clause}`, `spec_delete_goal {id, reason}`, and the three parallel `*_antigoal` tools (with `ceded_to` and `kept_in` parameters). The `*_delete_*` tools are new — pre-DJ-139 the spec model is append-only — but goal-layer deletion is real (a removed scope claim should disappear); the history event preserves the audit trail. The existing `spec_propose_decision` / `spec_propose_feature` / `spec_propose_strategy` / `spec_revise_*` tools gain optional `advances []string` and `respects []string` parameters; backwards compatible with existing callers.

7. **`refine goals` workflow reorganized as sync → iterate → cite.** Step 1: goal-layer bootstrap/sync (skipped on hash match). Step 2: existing `spec_refinement` playbook iteration, now reading `goal-*` / `agoal-*` nodes as context alongside `GOALS.md`. Step 3: citation walk, **last** so it operates against the final state of all nodes. Walking citations before iteration would target intermediate node states that get rewritten — exactly the misapplied-citation failure mode. Citation walk is metadata-only (`.advances` / `.respects` writes); it never modifies node content. Content cascading remains by-judgment in steps 2 and in normal refine/import/adopt flows.

8. **At-risk surface fires in step 3.** Features whose final state has empty `.advances` after the citation walk surface in the `refine goals` output AND persist as `status --full` validation warnings ("features without goal anchors — review needed"). Resolution is operator judgment; `refine goals` never auto-deletes features or auto-revises content based on goal-layer changes. The conflict-amplifying case (a Goal transitions to an AntiGoal via `GOALS.md` edit) lights up this surface so the operator sees affected features by name.

9. **Bootstrap affordance for existing projects.** On first `refine goals` for a project where `goal-*` / `agoal-*` nodes don't exist yet AND existing `dec-*` content encodes scope (the `dec-product-scope-boundary` pattern), the matcher prompt is extended with "for first-run bootstrap, treat decisions whose body enumerates scope claims as secondary sources alongside `GOALS.md`." This is a **one-time** behavior: subsequent passes drop the secondary-source affordance and read only `GOALS.md`. Lets winplan-style projects migrate without first having to flesh out an empty `## Out of Scope` section in `GOALS.md`. The original scope-encoding decisions stay as historical documentation post-bootstrap; the new `agoal-*` nodes are authoritative.

10. **Axes anchor at Goals only.** Per [DJ-124](dj-124-axes-from-goals-features-strategies.md) axes are surfaced from goals, features, and strategies; under DJ-139 axes anchor exclusively at Goal nodes. Features and strategies cite Goals via `.advances` and inherit the axis chain transitively. [DJ-133](dj-133-decisions-identified-by-axis.md)'s `dec-<axis-id>` decision-id shape stays intact. The inverse query "which Goal does this axis trace to?" is derivable via decision.advances + the axis structure.

11. **Import playbook gains a `GOALS.md` diff drafter.** `feature_ingestion.md` extends to read `goal-*` / `agoal-*` nodes alongside the manifest. Conflict detection becomes a structural graph-test against `agoal-*.body + .kept_in` instead of an LLM judgment over `GOALS.md` prose. When conflicts surface AND the feature plausibly fits under an extended/new carve-out, the playbook drafts a unified-diff block against `GOALS.md` and surfaces it for operator review — the operator applies the diff (manually or via a future `locutus apply-goals-diff` helper) and re-runs the import. On admission, the playbook populates the new feature's `.advances` and `.respects` via the propose tool's new optional parameters.

**Resolved design questions** (chat 2026-05-27):

1. **Authorship: `GOALS.md` stays canonical; goal nodes are LLM interpretation.** Humans only edit `GOALS.md`. The refine pass writes goal-*/agoal-* nodes as its persisted interpretation. Users can read them but don't author them directly. Matches Locutus's "humans author, Locutus implements" stance ([[feedback-locutus-voice-neutrality]]). Rejected: goal nodes as canonical with `GOALS.md` derived; bidirectional sync between the two.

2. **Granularity: atomic claim.** One node per discrete statement, regardless of `GOALS.md` formatting. Most semantically precise; gives the import flow fine-grained pivot points. Rejected: section-level (one node per `##` heading — too coarse for the cascade); bullet-level (one node per markdown bullet — risk of over-loaded bundled-claim nodes).

3. **AntiGoal as a separate node type, not an `out_of_scope` Goal kind.** Polarity encoded in the type, not a kind enum. Each polarity gets its own propose/revise/delete tool surface. Rejected: single `Goal` node type with a `kind` discriminator field; richer enum (`in_scope` / `out_of_scope` / `constraint` / `quality_bar`). The user's reframing that AntiGoal-as-separate-type matches the existing prefix-discriminated node-kind pattern (DJ-133's `dec-`, etc.) was the load-bearing observation.

4. **AntiGoal carve-outs live in a structured `kept_in []string` field, not freetext body.** Each entry is one sentence/clause naming what stays in scope despite the broader exclusion. The LLM consumes them alongside `body` when judging boundary navigation. Rejected: free-text body only (parsing inconsistency over time); spawning a paired Goal node for each carve-out (doubles node count without graph-operation payoff).

5. **`.advances` / `.respects` are informational dotted lines, not required invariants.** Optional `[]string` fields on existing kinds; empty/absent is fine. The graph never enforces structural citation discipline. Rejected: both fields required with empty arrays explicitly present (over-prescription noise the agent has to remember to emit; degeneracy concern that pre-DJ-135 direct-SDK calls had to defend against but DJ-135-era coding agents handle naturally via prose reasoning before tool-call); only `.advances` required non-empty for features/strategies (still over-prescriptive for the same reasons).

6. **Axes anchor at Goals only.** Tighter model than DJ-124's "surfaced from goals, features, and strategies" framing: under DJ-139, only Goal nodes anchor axes structurally. Features/strategies cite Goals; axes flow transitively. DJ-133's decision-id shape preserved. Rejected: axes dissolve into direct Goal→Decision references (would break DJ-133's id-stability guarantee); status quo with axes surfaced from features/strategies in addition (loses the "every axis traces to exactly one Goal" property that makes the audit chain tight).

7. **Diff-and-apply on `GOALS.md` change, never wipe-and-regen.** Goal/agoal IDs are referenced by `.advances` / `.respects` citations; wiping would break every citation on every edit. The matcher preserves IDs across rephrasings via `source_clause` comparison. Rejected: wipe and regenerate (breaks citation continuity); per-node hashing instead of project-level (denormalization without consumer); deterministic slug-only matching (text-similarity won't catch semantic-equivalence rephrasings).

8. **`refine goals` runs sync → iterate → cite (citation walk last).** The user's correction to an earlier design draft: walking citations before iteration targets intermediate node states that get rewritten. Walking last ensures citations match the final state of all nodes. Rejected: citation walk first (the misapplication failure mode); separate verb for citation walk (`locutus refine citations` — considered, rejected as over-fragmentation when the bundled flow is the canonical refresh).

9. **One-time bootstrap affordance for `dec-*-scope-boundary` pattern.** The matcher prompt gains a "treat scope-encoding decisions as secondary sources" branch only on first-run-with-no-goal-layer. Subsequent passes read only `GOALS.md`. Rejected: a separate `locutus migrate-goals` verb (extra surface area for a one-time operation); requiring operators to flesh out `GOALS.md` before the first sync (high friction for projects whose scope is already deliberated as decisions).

10. **No `spec_biased`-style cascade root event for `refine goals` runs.** The existing `spec_revised` event log already captures per-node writes; rolling them up into a synthetic `goals_synced` root event is navigation nicety, not a structural need. Re-evaluate if operators ask for "walk this sync's full footprint" affordance after empirical use.

**Alternatives considered:**

- **No goal layer; just persist a `goals_md_hash` and the structured interpretation in a sidecar JSON file.** Rejected — the failure modes require the interpretation to be *queryable* and *citeable* (the import playbook binds conflicts to specific goal/anti-goal claims). A sidecar file would force every consumer to parse it and bind by string-matching. Graph nodes with stable IDs are what the existing tooling already speaks.

- **Generate goals from specs first (inverse direction), use that as the persisted interpretation.** Considered earlier in the brainstorm as "infer goals from specs and detect alignment drift against `GOALS.md`." Rejected as architecturally heavy without a concrete pain point; the forward direction (`GOALS.md` → persisted interpretation) solves the original failure modes directly. The inverse direction may revive as a Future Work item if operators start asking "what goals does my current graph actually imply?" — but the structured goal layer DJ-139 introduces is a prerequisite for that direction anyway, so this DJ doesn't preclude it.

- **Single `Goal` node type with `kind: in_scope|out_of_scope` enum.** Rejected as discussed in resolved-question 3 — the user's reframing of AntiGoal as a separate first-class type was cleaner. Polarity-in-the-type matches the prefix-discriminated node model and eliminates a per-read enum check.

- **Required `.advances []goal-*` non-empty on every feature; rejected at the propose-tool level when empty.** Considered as a way to catch orphan features. Rejected per resolved-question 5 — coding-agent runtimes don't need this defensive prescription, and the at-risk surface in step 3 catches orphans for the operator without forcing the agent to emit empty arrays when no citation is appropriate.

- **Structured `Status: active|proposed|removed` field on `Goal` and `AntiGoal`.** Considered for symmetry with the existing kinds (Decision has `status`, Feature has `status`). Rejected per [[feedback-no-aspirational-fields]] — goals are LLM interpretation of human-authored text; they collapse to either "active" or "removed by next refine" with no meaningful in-flight state. Add later when a real consumer emerges.

- **`surfaces_axes []string` field on `Goal`.** Considered for denormalized query convenience ("which axes does this goal anchor?"). Rejected as denormalization without an immediate consumer — the inverse query is derivable from `decision.axes` + `decision.advances`. Add later if query frequency justifies it.

- **Wipe `goal-*` / `agoal-*` on every `GOALS.md` change and regenerate.** Rejected per resolved-question 7 — IDs are citation targets; wiping breaks citations on every edit.

- **A new `locutus seed-goals` verb instead of folding the bootstrap into `refine goals`.** Considered for explicit operator control over the one-time bootstrap cost. Rejected as over-fragmentation; the bootstrap is just step 1 of `refine goals` when the hash is absent, and the rest of the workflow (iterate, cite) is the same as a regular refine.

**Future Work (tee'd up for follow-up DJs):**

- **Witness-state precision for citation drift.** When a goal's body changes, the citation walk currently re-judges every node that cites it. Hash-based change detection on goal bodies + a `last_judged_against_hash` per-citation field could short-circuit the walk for goals whose changes are textual rather than semantic. Parallel to DJ-138's deferred Phase-2 work.

- **`locutus refine goal-X --with "<bias>"` and `locutus refine agoal-X --with "<bias>"`.** Strong-bias revision of a goal-layer node, with cascade through downstream citing features (DJ-138 cascade machinery applies; the spec_bias playbook just needs the new node-kind prefixes added to its target-validation logic).

- **`locutus apply-goals-diff <patch>` helper.** Small utility that applies the import playbook's drafted `GOALS.md` diff for the operator. Trivial to add once the import flow's diff output format is stable.

- **`locutus drift goals` verb (inverse-direction alignment detector).** "Generate goals from current graph state and compare against `GOALS.md`" — surfaces goals the graph implies that aren't in `GOALS.md`, and goals in `GOALS.md` that no graph nodes advance. Was considered during the DJ-139 brainstorm as a possible primary direction; deferred until concrete operator demand surfaces. The DJ-139 goal layer is a prerequisite for any such inverse-direction tool, so this DJ doesn't preclude it.

- **`goals_synced` root history event** rolling up the per-node writes from a single `refine goals` run into a walkable subtree (paralleling DJ-138's `spec_biased` root event pattern). Adds navigation affordances but no structural correctness; defer until a real consumer asks.

- **Per-runtime playbook overlay** for the goal-layer playbook. Defer until a real UX win surfaces (matches DJ-138's stance on overlays).
